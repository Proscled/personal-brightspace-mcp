# Claude setup

The local server uses newline-delimited JSON-RPC over stdio, the transport supported by Claude Desktop and Claude Code for local MCP servers. There is no Claude-specific remote endpoint, extra account permission or API key for the MCP host. A school's authentication and permission requirements still apply separately.

## Claude Desktop

Install Node.js 22.16+ and keep this project in a permanent location. On macOS, run `bash setup.sh` from that folder. On Windows, run `npm ci --ignore-scripts` and `node scripts/smoke.mjs` in PowerShell instead. Both use the included `dist/` build.

Run this command in the same project folder:

```bash
node dist/index.js config-client --client claude-desktop
```

The output is valid JSON with your absolute Node path, server path and state-directory path. It contains no tokens or cookies. The generator does not read saved configuration, credentials, imported notes or baselines and does not modify Claude's files.

In Claude Desktop, choose **Settings → Developer → Edit Config**. Add the printed `brightspace` object under `mcpServers`. Keep other entries. For a new or empty configuration file, use the whole printed JSON document.

| Operating system | Claude Desktop configuration |
| --- | --- |
| macOS | `~/Library/Application Support/Claude/claude_desktop_config.json` |
| Windows | `%APPDATA%\Claude\claude_desktop_config.json` |

Save, completely quit Claude Desktop, and reopen it. Inspect `brightspace` in the local MCP settings or the connector menu in chat. Ask Claude to call `brightspace_status` with `verifyConnection: false` first. An unconfigured authentication status is expected before authorized school sign-in. Do not treat it as a successful school connection.

The JSON uses the same `mcpServers` structure as [examples/mcp-config.json](../examples/mcp-config.json). Use generated paths rather than copying that example's placeholders. On Windows, the generated JSON automatically escapes backslashes.

## Claude Code

In Bash/zsh, print your registration command:

```bash
node dist/index.js config-client --client claude-code
```

Review and run the printed `claude mcp add` command. It selects local stdio and user scope, sets only the state-directory path, and does not include credentials. For a PowerShell terminal, use:

```powershell
claude mcp add --scope user --transport stdio brightspace -- (Get-Command node).Source "$((Get-Location).Path)\dist\index.js" serve
```

The PowerShell command uses the default state directory. If you set a custom `BRIGHTSPACE_MCP_HOME` during sign-in, configure that same directory in the server's environment as well.

Then check:

```bash
claude mcp get brightspace
```

Use `/mcp` in a Claude Code session to view the server and its tools. First use the local-only status check described above. Connecting either Claude host does not automatically import files, sign in or access school data.

## Troubleshooting

- **Server missing or fails to start:** validate the JSON, keep the absolute paths generated by `config-client`, verify Node.js 22.16+, and fully restart Claude Desktop. Do not move/delete the project folder after registration. Generate the settings again if you move it or change Node installations.
- **Server starts in Terminal but fails in Claude:** desktop apps may have a different PATH or working directory. Use the generated absolute executable and script paths. The server does not require the project as its working directory.
- **Authentication missing:** sign-in must be completed separately in a normal terminal, using the same state directory as Claude. Follow [authentication](AUTHENTICATION.md) only when your institution authorizes the use. Do not paste sessions, cookies or tokens into chat or GitHub issues.
- **401 or 403:** school permissions may deny the endpoint even after successful sign-in. The server reports this; it does not bypass the denial.
- **Long multi-course request:** narrow the request to one course or resource and paginate results. Client timeout limits can interrupt longer operations. See the current Claude Code reference for its MCP timeout settings.
- **Document or slide rendering unavailable:** macOS PDF/OCR requires its native frameworks; Office rendering requires the local dependencies described in the README. Protocol connectivity does not verify every document format.

Claude Desktop MCP logs are normally under `~/Library/Logs/Claude` on macOS and `%APPDATA%\Claude\logs` on Windows. Inspect them locally; redact account/course data and credentials before sharing diagnostics.

## Verification limits

The synthetic test suite checks the generated Claude Desktop command from a different working directory, paths with spaces, every advertised stdio protocol revision, tool discovery, local status and safe error reporting. These checks do not establish a live Claude UI connection or live school access. See [test report](TEST_REPORT.md).
